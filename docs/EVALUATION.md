# 평가 기준

평가 대상은 [DMS 확정 구현 계획](IMPLEMENTATION_PLAN.md)의 기능과 데이터셋으로 제한한다. 현재 테스트 통과는 실제 데이터 성능을 의미하지 않는다.

| 기능 | 데이터셋 | 핵심 지표 |
| --- | --- | --- |
| 눈 개폐·EAR | MRL Eye, AI Hub 졸음운전 | Accuracy, F1 |
| 하품·MAR | YawDD, AI Hub 졸음운전 | 검출률, 오경보율 |
| 졸음 경고 | AI Hub 졸음운전, UTA-RLDD Fold 1~4 | F1, 이벤트 Recall, 탐지 지연 |
| 고개 방향 | AI Hub 졸음운전, 자체 웹캠 | 각도 오차, 정확도 |
| 휴대폰·음료 | State Farm, AI Hub 이상행동 | Macro F1, mAP |
| 전체 시스템 | 자체 웹캠 시나리오 | FPS, 평균·p95 지연, 프레임 드롭률 |
| 경고 | 라벨 영상 | 오경보/분, 미탐, 탐지 지연 |

## 비교 실험

1. 눈 개폐: MediaPipe EAR 단독과 EAR+OpenVINO 교차 판정
2. 하품: 단일 MAR 임계값과 개인 보정+지속시간 판정
3. 주시: Head Pose 단독과 Head Pose+홍채 상대 위치
4. 행동: State Farm 분류와 AI Hub YOLO11 검출
5. 통합: 개별 모델과 3개 모델 동시 실행의 속도·오경보

## 측정 프로토콜

- 운전자와 촬영 세션을 train/val/test 사이에 중복시키지 않는다.
- 설정 선택은 val에서만 수행하고 test 결과로 임계값을 다시 맞추지 않는다.
- Accuracy, Macro F1, 클래스별 Precision/Recall, 혼동행렬, 평가 수를 함께 기록한다.
- YOLO 검출은 클래스별 AP와 mAP를 기록한다.
- `unknown`과 `uncertain`을 제거하지 않고 전체 입력 대비 비율을 보고한다.
- 이벤트 시작·종료, 매칭 허용 지연, 중복 경고 처리 규칙을 평가 전에 고정한다.
- FPS는 640×480에서 총 처리 프레임/실제 경과 시간으로 측정한다.
- 평균·p95 지연, 입력 FPS, 처리 FPS, 드롭 비율, 워밍업 제외 정책을 기록한다.
- CPU/GPU·OS·모델·데이터 버전·커밋·설정 해시를 결과에 남긴다.
- 안경·가림·역광·야간·측면·카메라 위치를 조건별로 분리한다.

## 초기 완료 기준

- MediaPipe·OpenVINO eye·YOLO11 동시 실행
- 640×480 처리 속도 15 FPS 이상
- 눈 감김·하품·고개 이탈·휴대폰·음료의 데이터셋별 정량 결과
- 프레임 및 이벤트 로그에 모델 점수와 판단 근거 저장
- 오경보/분·미탐·탐지 지연 보고
