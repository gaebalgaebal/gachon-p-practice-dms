# 평가 기준

모든 수치는 계획서의 **제안 목표**이며 달성 성능이 아닙니다. 데이터·평가 PC·라벨 정의와 멘토 협의 후 확정합니다. 초기 특징 규칙의 단위 테스트는 아래 지표의 실험 결과를 대신하지 않습니다.

| 평가 대상 | 계획 목표 | 조건 |
| --- | --- | --- |
| 졸음 3상태 | Macro F1 ≥ 0.80 | 운전자 분리·각성/저주의/졸음 라벨 대응 모델 필요 |
| 전방 주시 2상태 | Macro F1 ≥ 0.80 | 주시 정의·라벨 확보 시 |
| 행동 분류 | Macro F1 ≥ 0.75 | 실제 확보한 클래스만 평가 |
| 실시간 처리 | ≥ 10 FPS | 640×480, 평가 PC 확정 후 재설정 |
| 시간 안정화 | Baseline 대비 분당 오경보 감소 | 동일 영상·동일 이벤트 기준 |

## 비교 실험

1. 졸음: 단일 프레임 EAR vs 연속 감김·시간창 비율. 3상태 분류는 별도 라벨 대응을 설계하며 현재 binary 규칙 결과를 3상태 성능으로 보고하지 않음.
2. 주시: Head Pose 단독 vs 얼굴 방향+눈 관련 특징. 실제 gaze와 얼굴 방향 프록시 결과를 구분.
3. 행동: 동일 데이터 분할의 간단 분류기 vs MobileNetV3-Small 전이학습.
4. 통합: 개별 모듈 vs 동시 실행의 FPS·지연·메모리·오경보.

## 측정 프로토콜

- 모델/설정 선택은 val에서만 수행. test 운전자·촬영 세션을 train/val에 포함하지 않음.
- Accuracy, Macro F1, 클래스별 Precision/Recall, 혼동행렬, 평가 수를 함께 보고.
- unknown을 조용히 제거하지 않음. 전체 입력 수·유효 라벨 수·unknown 비율과 coverage(판단 가능한 비율)를 함께 기록.
- 유효 예측만의 점수와 전체 라벨 구간에서의 경고 누락을 구분. unknown 처리 규칙을 결과표에 명시.
- 이벤트 정의(시작/종료, 지속시간, 매칭 허용 지연, 중복 경고 처리)를 평가 전에 고정.
- 오경보/분 = 실제 음성 구간의 잘못된 경고 이벤트 수 / 실제 음성 구간 길이(분). 경고 프레임 수와 구분.
- 탐지 지연 = 정답 이벤트 시작부터 최초 유효 경고까지. 미탐 이벤트는 지연 평균에서 누락 처리하지 말고 별도 미탐률로 보고.
- FPS는 총 처리 프레임/실제 경과 시간. 입력 FPS·처리 FPS·드롭 비율, 평균/p95 종단 지연, 워밍업 제외 정책 명시.
- 해상도·CPU/GPU·OS·모델·배치·평가 영상·측정 시간·커밋·설정 해시 기록.
- 얼굴 미검출·안경·가림·역광·야간·측면·카메라 편차를 조건별로 분리.
- 데이터셋 평가와 실제 웹캠 시연은 별도 표로 관리.
