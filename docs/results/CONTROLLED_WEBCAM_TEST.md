- 2026-11-10, `/dev/video0`, 640×480, 수동 노출 120
- MediaPipe Face Landmarker + OpenVINO eye + AI Hub YOLO11n
- 녹화·이미지 저장 없이 JSON 상태 로그만 저장
- 1차: 정면, 눈 감기, 회복, 고개 돌림, 하품, 휴대폰 순서로 660프레임

1차 시험은 얼굴 유효 575/660프레임, 정상상태 15.00 FPS였다. 눈 감기와 하품은 실제 warning 이벤트까지 연결되었다. 고개를 크게 돌리면 얼굴 랜드마크가 먼저 유실되어 주시 이탈보다 `unknown`으로 안전하게 전환됐지만, 요구하는 `off_forward` 상태를 안정적으로 만들지는 못했다.

휴대폰 집중 시험에서는 얼굴이 324/330프레임 검출되고 보정 상태가 298프레임 유지됐으므로 얼굴 파이프라인 문제는 아니다. 낮은 confidence에서도 후보 점수가 임계값에 미치지 못해, AI Hub 몸 전체 행동 박스와 현재 근거리 웹캠 구도 사이의 도메인 차이가 실제 환경에서 재현됐다. 현 YOLO 행동 모델은 연구용 비교 기준으로 유지하고 운영 경고에는 승격하지 않는다.

원시 결과는 `runs/webcam_controlled_scenario_20261110`과 `runs/webcam_phone_focused_20261110`에 있다.

## 고개 돌림 추적 개선

얼굴 유실만으로 시선 이탈을 추정하지 않고, 유실 직전에 yaw·pitch·gaze가 이미 한계를 넘은 경우에만 attention 타이머를 최대 2초 유지하도록 개선했다. 눈 감김과 하품 타이머는 얼굴 유실 즉시 초기화하므로 가림 시간이 졸음이나 하품 시간으로 누적되지 않는다.

기존 660프레임 현장 로그를 새 상태 엔진에 같은 순서로 재생한 결과, `off_forward`가 기존 0프레임에서 81프레임으로 증가했다. 이 중 얼굴 미검출 상태에서 추적된 구간은 고개를 왼쪽으로 크게 돌린 직후였고, 정면 상태에서 시작된 얼굴 유실은 계속 `unknown`이었다.

실시간 재시험 두 차례는 `/dev/video0`에서 얼굴이 0/390프레임으로 들어와 판정 대상에서 제외했다. 수동 노출과 자동 노출 모두 동일했으므로 로직 결과로 해석하지 않으며, 카메라 구도를 다시 확인한 뒤 최종 현장 재시험한다.

카메라 재탐색 후 최종 390프레임 시험에서는 얼굴 313프레임, 보정 상태 342프레임, 정상상태 15.000 FPS를 기록했다. `off_forward` 경고가 두 번 발생했고, 얼굴 미검출 상태에서도 직전 회전 추적에 의해 18프레임이 `off_forward`로 유지됐다. 좌측 회전과 얼굴 유실 연결은 확인됐지만 우측 회전 구간은 대부분 `forward`로 판정되어 좌우 자세·카메라 각도 비대칭은 추가 튜닝 대상으로 남긴다. 원시 결과는 `runs/webcam_head_tracking_v2_final_20261110`에 있다.
