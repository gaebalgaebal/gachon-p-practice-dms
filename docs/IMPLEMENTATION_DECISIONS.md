# 구현 기준과 결정 대기 항목

메일과 확정 기획서를 기준으로, 멘토 답변 없이 진행 가능한 공통 기반을 먼저 구현합니다. 아래 결정은 기능을 막지 않도록 코드에서 확장 가능한 상태로 유지하되, 성능 목표나 최종 완료 판정에는 멘토 답변을 반영합니다.

## 멘토 결정 대기

1. 졸음은 `normal/suspected` 징후 탐지면 충분한가, `alert/low_vigilance/drowsy` 3단계가 필수인가?
2. 전방 주시는 얼굴 방향 기반 프록시를 허용하는가, 보정된 눈 방향 결합이 최종 필수인가?
3. 최종 필수 행동은 통화·음료까지인가, 취식·흡연도 필수인가?
4. 최종 평가 PC·카메라와 최소 FPS 기준은 무엇인가?

## 답변 전 구현 범위

- 실제 웹캠 연결과 프레임 품질을 영상 저장 없이 검사한다.
- MediaPipe 얼굴 랜드마크에서 EAR, 얼굴 yaw/pitch, 홍채 상대 위치를 얻는다.
- 정면 보정값 대비 얼굴·홍채 이탈을 같은 시간 규칙으로 결합한다.
- 홍채 특징을 얻지 못하면 기존 Head Pose Baseline으로 동작하고 로그에 근거를 남긴다.
- `unknown`을 정상으로 바꾸지 않고 프레임·이벤트 평가에서 별도로 집계한다.
- 통화·음료·취식·흡연 데이터가 들어올 수 있는 manifest와 학습 경로를 유지한다.

## 보유 모델과 학습 필요성

| 기능 | 현재 모델 또는 방법 | 별도 학습 | 현재 의미 |
| --- | --- | --- | --- |
| 얼굴·눈·홍채 랜드마크 | 공식 MediaPipe Face Landmarker 사전학습 모델 | 불필요 | 모델 파일 다운로드 후 즉시 사용 가능 |
| 눈 감김 징후 | EAR·개인 보정·지속시간 규칙 | 불필요 | 규칙 임계값은 실제 영상으로 검증 필요 |
| 얼굴 방향 | Face Landmarker 변환 행렬 | 불필요 | 실제 gaze가 아닌 Head Pose 프록시 |
| 눈 방향 | 홍채의 눈 내부 상대 위치·개인 보정 | 초기에는 불필요 | 실제 시선 벡터가 아닌 RGB 카메라용 프록시 |
| 졸음 3단계 | 없음 | 필요 | UTA-RLDD 같은 라벨 영상과 temporal 모델 필요 |
| 통화·음료·취식·흡연 | MobileNetV3-Small 구조와 학습 코드만 존재 | 필요 | ImageNet 가중치는 운전자 행동 완성 모델이 아님 |

따라서 1차 실시간 데모는 사전학습 Face Landmarker와 규칙으로 완성할 수 있습니다. 행동 인식과 3단계 졸음 분류는 데이터 기반 학습 없이 완료되었다고 볼 수 없습니다.

## 데이터 도입 순서

1. DMD의 현재 공개 범위·사용 조건을 확인하고 gaze/fatigue/action 라벨 변환기를 작성한다.
2. UTA-RLDD는 운전자 단위 분할로 3단계 졸음 실험에만 사용한다.
3. State Farm은 normal/phone/drink 행동 Baseline 후보로 사용한다.
4. eat/smoke는 합법적인 공개 데이터가 부족하면 멘토와 자체 촬영 여부를 결정한다.

원본 얼굴 영상, 추출 프레임, 개인 식별 정보는 Git에 커밋하지 않습니다. 데이터 라이선스와 학습 가중치 재배포 가능 여부도 별도로 기록합니다.

## 평가 기준

- 프레임: Accuracy, Macro F1, 클래스별 Precision/Recall, 혼동행렬, unknown coverage
- 이벤트: 이벤트 Recall/Precision, 미탐 수, 오경보/분, 탐지 지연
- 시스템: 처리 FPS, 평균·p95 루프 시간, 카메라 읽기 실패, 10분 연속 실행
- 조건별: 안경, 가림, 역광, 야간, 얼굴 회전, 카메라 위치

계획서의 F1과 FPS 수치는 목표치이며, 실제 측정 전에는 달성값으로 기록하지 않습니다.
